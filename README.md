# Siemphony Detection Corpus

**400 machine-authored, adversarially reviewed Sigma detection rules** for
[MITRE ATT&CK](https://attack.mitre.org/) v19, covering **402 techniques**,
each translated to up to four SIEM dialects. This repository mirrors the
public corpus at [siemphony.com](https://siemphony.com) — every rule links
back to its page, where it carries a live noise check, a micro-lesson and its
verification evidence.

## Read this before deploying anything

These rules are **machine-authored and, except where marked, never executed
against live telemetry**. Every rule carries Sigma `status: experimental`.
They were authored from MITRE's own detection strategies and passed an
adversarial review (97% yield — what failed review was not published), but a
rule that has not run against your telemetry is a starting point to fork and
tune, not a deployable ruleset. 37 rules currently carry a
verification badge earned by firing correctly on real attack captures in the
[Siemphony lab](https://siemphony.com) — marked ✅ below.

The honest gaps are documented too: six techniques were deliberately left
with **no rule at all**, because the truthful answer was that there is
nothing reliable to detect there — publishing a plausible-looking rule that
cannot work is worse than publishing nothing.

## Layout

```
rules/<technique>--<slug>/
  rule.yml        Sigma source (the canonical artifact)
  splunk.spl      Splunk SPL          — when expressible
  sentinel.kql    Microsoft Sentinel  — when expressible
  elastic.esql    Elastic ES|QL       — when expressible
  wazuh.xml       Wazuh rule XML      — when expressible
```

A missing query file is deliberate: the translator **refuses rather than
guesses** when a backend cannot express a construct, because a query that
runs and silently matches nothing is the worst outcome a detection can have.
The per-rule pages explain each refusal.
